# KTS 插件工坊 —— 详细设计（v1）

> 目标：小白拖控件 → 连线 → 填参数 → 预览代码 → 导出**可直接加载**的模块化 `.kts` 插件。
> 只做"写"：不执行、不加载、不编译、不跑游戏。
> 本设计的代码生成目标 = **工作区 `ScriptAgent4MindustryExt-3.4.0-scripts/` 的真实 API**，不是 `要求.txt` 里的示意语法。

---

## 0. 对 `要求.txt` 的三处修正（重要）

设计前必须纠正三处与真实环境不符的地方，否则产出的文件丢进 `scripts/` 不会被加载。

### 修正 1：`plugin.json` 不是脚本插件的元信息

`要求.txt` §3 把 `plugin.json` 列为导出物。实际上 `plugin.json` 是 **Mindustry 加载器 jar 自己的** Bukkit/Mindustry 插件描述符：

```json
{ "name": "ScriptAgent4Mindustry", "author": "WayZer",
  "main": "cf.wayzer.scriptAgent.mindustry.Loader",
  "description": "More commands and features.", "version": "3.4.0", "minGameVersion": 147 }
```

（来源：本机 `ScriptAgent4MindustryExt-3.4.0.jar` 内的 `plugin.json` / `plugin.yml`。）

脚本目录 `scripts/` 里**没有** `plugin.json`，只有 `.kts` / `.kt` / `.metadata`。SA 不会读生成物里的 `plugin.json`。
**结论**：导出物 = `模块名/module.kts` + 各画布的 `xxx.kts`，**不生成** `plugin.json`（已按你的选择确定）。

### 修正 2：入口不是 `plugin.kts`，而是 `module.kts`

`要求.txt` §3 的 `plugin.kts`"注册所有模块"在 SA 里没有对应概念。真实的模块声明是 `module.kts`（目录级依赖与默认导入）：

```kotlin
// coreMindustry/module.kts
@file:Depends("coreLibrary")
@file:Import("coreMindustry.lib.*", defaultImport = true)
package coreMindustry
```

且 SA **自动收集**目录下所有 `.kts`，无需手工注册。所以"注册所有模块"这一步在 SA 里是多余的。

### 修正 3：`Events.on(...)` 换成 `listen<T>{}`

真实写法（工作区处处可见）：

```kotlin
listen<EventType.PlayerJoin> { it.player.sendMessage("...".with()) }   // 类型事件
listen(EventType.Trigger.update) { ... }                               // 触发器
```

`listen` 是 `coreMindustry.lib.ListenExt` 里 `Script` 的扩展函数，顶层隐式 `Script` 接收者即可直接调用。

| 55 | 单例弹窗不能再叠 | `#modal` 只有一个容器，在前一个弹窗的按钮回调里直接 `await this.confirm(...)` 会把前者顶掉，而前者的 Promise 永远悬着。正确做法是先抓住 `this.modalDone` 收起自己，再开下一个 |
| 56 | `[data-btn]` 之外要自己挂事件 | `modal()` 只给 `[data-btn]` 自动挂 click。body 里塞的自定义可点元素必须自己 `addEventListener`，否则点了没反应（欢迎页卡片和模块列表的删除键都踩过） |
| 57 | 源码编码自检 | Windows PowerShell 5.1 的 `Get-Content` 按 ANSI 解码、`Out-File -Encoding utf8` 写回，一次往返就把整个文件的 UTF-8 中文变成 GBK 乱码 —— 而文件仍是合法 JS，`node --check` 和所有单元测试**都不会报错**。真发生过一次（`canvas.js`）。所以加了 `tests/encoding.js`：查 U+FFFD、查 GBK 乱码特征字、反查关键文件中文是否还在、查行数有没有被压扁 |
| 58 | 被破坏后的恢复途径 | 工程不是 git 仓库，但 `verify-embed` 证明过 exe 里嵌着逐字节一致的前端副本。用 `zlib.brotliDecompressSync` 解开 `target/release/build/*/out/tauri-codegen-assets/` 里的资源即可还原（按 `export class CanvasView` 等特征认文件，用字节数核对） |
| 59 | 深色模式下的「同色看不见」 | 节点类型小标签写死了 `background: rgba(255,255,255,.7)` + `color: var(--fg-2)`。浅色下正常，深色下 `--fg-2` 变成浅色 → **白底白字**。修法不是改那一个值，而是加 `--nc-chip` / `--nc-chip-fg` 两个变量、两套主题各给一份；同时给 `tests/css-vars.js` 加第 6 组：查「写死的半透明白/黑」——老检查只查十六进制字面量，`rgba()` 从它眼皮下漏过去了 |
| 60 | 左键拖空白处 = 平移画布 | 用户明确要求。这与「左键框选」冲突，取舍：左键拖空白处平移（点一下顺便取消选中），**框选让位给 Shift+左键**。右键/中键/空格+左键拖仍可平移，习惯不变 |
| 61 | 全局防崩溃 | 「点哪个按钮都弹报错/卡住」的根因是：几乎所有按钮最后都走 `renderAll()` → `refresh()` → `generatePlugin()`，一处抛异常就全线不动。三层兜底：① `crashguard.js` 最先加载，拦 `error` + `unhandledrejection`；② `renderAll()` 按环节（标签页/控件库/画布/参数面板/状态栏）分别 try/catch，一处坏不拖垮其余；③ 工具栏动作抽成 `dispatch(act)` 统一兜住。报错框给「关掉提示继续用 / 另存工程 / 复制详细信息 / 隐藏」四条出路，同一错误最多提示 3 次（避免刷屏盖死界面） |
| 62 | 版本号单一来源 | 只允许在仓库根 `VERSION` 手写一次，`tests/sync-version.mjs` 在编译前把它写进 `Cargo.toml`、`tauri.conf.json`、`src/frontend/js/version.js`。Rust 侧 `app_version()` 用 `env!("CARGO_PKG_VERSION")` 返回编译期常量，所以「设置里显示的版本」和「exe 属性里的版本」必然是同一个。`tests/version-license.js` 在 --check 模式下守住这件事 |
| 63 | 开源协议 | MIT，版权人「烛光」（用户指定）。`LICENSE` 是唯一原文，设置页「关于」里显示的协议名与版权人由 `tests/version-license.js` 核对，避免「LICENSE 写 MIT、界面显示 Apache」这种不一致 |
| 64 | 目录结构与「设置」一样是产品的一部分 | `src/frontend/`（前端）/ `src/backend/`（Rust）/ `tests/` / `docs/`，根目录只留 exe、build.ps1、VERSION、LICENSE、README。**移动目录后必须删掉 `target/` 和 `gen/`**：Tauri 的构建脚本会把绝对路径烘进 `target/release/build/.../out/permissions/`，目录一挪就报「系统找不到指定的路径」 |
| 65 | 批量改路径不能用 PowerShell | 重排目录时用 node 做前缀替换（`'ui/js` → `'src/frontend/js`）。**规则不能带结尾引号**：第一版写成 `join(ROOT, 'ui/js'`，而实际代码是 `join(ROOT, 'ui/js/model.js')`，引号在 `model.js` 后面，于是规则匹配不上、6 个测试全在找不存在的 `ui/`。按路径前缀替换才对 |
| 66 | 崩溃日志落盘 | 用户报「有几个按钮一点就崩溃」但复现不出来时，光靠口头描述定位不了。所以任何未捕获异常都**追加**写进 exe 同目录的 `crash.log`（追加而非覆盖：连踩几个错时前面的不能丢），带时间戳和版本号。报错框里直接显示日志路径，并给一个「打开日志文件夹」按钮。写在 exe 旁边而不是 `%LOCALAPPDATA%`，是因为用户找得到。写日志失败绝不抛异常 —— 一条日志写不进去，不能让工具二次崩溃 |
| 67 | 划框多选整块删除 | 用户明确说「框选我用不上，删了也行」。于是删掉元素、CSS、`this.marquee` 状态、绘制函数与 mousemove/mouseup 里的分支 —— 不留半死的代码。要同时选多个节点就按住 Ctrl 逐个点。`ui-structure.js` 加了一条反向断言：源码或 CSS 里再出现 `marquee` 就判失败 |
| 68 | 测试不许污染仓库 | `live-ui.js` 会故意写日志来验证落盘。因为日志位置是「exe 旁边」，直接在项目根跑就会往仓库里丢文件。所以测试**先把 exe 复制到临时目录再运行**，日志落在临时目录，收尾时连 profile 一起删 |
| 69 | **原生对话框卡死主窗口（真事故）** | 用户报「点 保存 / 从代码导入 / 导出插件 就卡住」。两个叠加的原因：<br>① 三个命令原来写的是**同步**命令（`fn foo()`）。Tauri 对同步命令用 `ExecutionContext::Blocking` → 生成 `"sync"`（tauri-macros 的 `command/wrapper.rs:266`）→ **在主线程上直接调用**，而主线程同时负责窗口消息循环。命令体里又 `thread::spawn(..).join()` **死等**模态对话框结束，主线程再也不派发消息。<br>② 对话框 owner 取的是 `GetForegroundWindow()`，它返回**全系统**的前台窗口。实测抓到 owner 是另一个进程（DeepSeek Harness 主窗口）—— 对话框挂到别的程序底下，**用户根本看不见它**，只看到应用卡住。<br>判定手法：给窗口发 WM_NULL 等回执（`SendMessageTimeout`），即 Windows 判定「无响应」的同一机制。修前测到 `HUNG`，且同一时刻渲染进程仍能应答 `1+1`（证明卡的是主线程不是页面）。<br>修法：命令改 `async fn` + `spawn_blocking`，owner 改用 `Window::hwnd()`。注意 `HWND` 在 windows-sys 里是裸指针、不实现 `Send`，跨线程要传 `i64` 再还原 |
| 70 | 日志系统 | 用户要「增加日志功能，使用 .txt」。写在 exe 旁的 `logs\kts-builder-YYYY-MM-DD.txt`（按天分，单文件不会无限膨胀），**崩溃也并进同一个文件**（不再单独出 crash.log）—— 一个文件看完所有事情，排查时不用在两处对时间。<br>**记什么**（用户指定）：错误与警告**逐条**列出（带模块/画布/控件，只说「3 个错误」过两天等于没记）、耗时（按钮响应 + 关键操作内部）、崩溃（堆栈 + 现场快照）、启停。<br>**不记什么**：生成的 Kotlin 代码。用户明确说不要 —— 它占地方，而且代码是「画布 + 参数」推出来的，画布和参数本身已在别的记录里。测试里有反向断言守着。<br>两个关键的**降噪**设计：`refresh()` 在几乎每次交互后都跑，所以①生成耗时只在 ≥50ms 时才记（否则被上千条「3ms」淹掉）；②校验问题集合变化时才记（否则填参数时每个字符都重写一遍同一批错误） |
| 71 | 崩溃现场快照 | 光有堆栈只知道崩在哪，不知道「当时在编辑多大的工程、崩溃前点了什么」。所以崩溃记录额外附两样：<br>①**工程规模**（N 个模块 / N 个画布 / N 个控件 / N 条连线 + 当前画布名）—— 3 个控件的画布崩了和 300 个控件的工程崩了完全是两码事；<br>②**崩溃前的操作轨迹**（最近 40 步，带时间）。<br>轨迹**只在内存里转、不落盘**：给每次点击都写一行盘太吵，只在真出错时才由 crashguard 一次性附上去。取值都各自 try/catch —— 崩溃处理路径里绝不能再因取信息而二次出错（工程对象可能已经损坏）。<br>`crashguard.js` 不 import 任何业务模块（必须在 App 坏掉时仍能独立工作），所以现场信息由 App 通过 `window.__app.captureSnapshot()` 提供 |
| 72 | 轨迹合并要归一化再比 | 一次点击会先 `action()`（记「点了什么」，写的是 `按钮: fit`）再 `begin().end()`（记「花了多久」，key 是 `按钮 fit`）——**一个带冒号一个不带**。第一版轨迹合并直接比字符串，于是永远匹配不上，每次点击都占两条，40 条的缓冲一半是重复的，崩溃现场看到的就是「按钮: fit」紧跟着「按钮 fit (1ms)」。修法是抹掉冒号和空白再比。这个 bug 结构测试和端到端测试都看不出来（它们只查「有没有记录」），是写 `tests/log-unit.js` 单测才暴露的 |
| 73 | 日志开关的绑定时机 | 把「记录日志」开关的事件监听写在模块加载时，而不是 `initLog()` 里。`initLog()` 是异步的（要先问路径），绑在里面的话「它跑完之前用户改了设置」那次改动会被丢掉 —— 「关了日志却还在写」这种 bug 极难查。是单测第 8 组抓到的 |
| 74 | 删连线的交互取舍 | 用户选「鼠标移到连线上浮出 ×，点它删除」。不用右键菜单是因为画布早有「右键拖动 = 平移」的手势，挂菜单会打架；不用双击是因为双击容易在拖拽收尾时被误触发。× 摆在贝塞尔曲线**参数中点**（`t=0.5` 时 `(P0+3P1+3P2+P3)/8`），必须和画线函数用同一组控制点，否则按钮会飘在线旁边。<br>节点右键菜单的「断开所有连线」要等 **mouseup 且没拖动过** 才弹 —— 右键按下就弹的话，每次想平移都会先闪一个菜单 |
| 75 | 「全屏」不记忆 | 用户明确选「不记住，每次普通窗口」。真全屏（无边框、盖住任务栏），F11 / Esc / 工具栏按钮都能切。Esc 有弹窗时优先关弹窗 —— 否则全屏退了、弹窗还开着更让人迷惑。全屏命令走自定义 Rust 命令而非窗口插件：插件命令要过 ACL，而本工程没有 capabilities 清单 |
| 76 | `const api = exporter` 是错的 | 全屏/日志命令挂在 `export.js` 的 **`api`** 对象里（`export const api = {...}`），不在模块顶层。第一版在 ui.js 顶部写了 `const api = exporter`，于是 `api.setFullscreen is not a function` —— 而且这个错误只在**点全屏按钮**时才暴露，结构测试查不出来，是 `live-ui.js` 真的去点才抓到的。**教训：结构断言能证明「代码写了」，只有真跑才证明「接对了」** |
| 77 | 测试等「就绪」而不是睡固定秒数 | live 测试原来都是 `setTimeout(1800)` 这类死等。机器空闲时够，但构建到第 6 步时后台还有别的活儿，启动明显变慢 —— 测试抢在 `canvas.js` 建出 `.cv-viewport` 之前就 `querySelector`，拿到 `null`，报出 `Cannot read properties of null (reading 'getBoundingClientRect')`。这是**假失败**：工具没问题，是测试等得不够。<br>改成轮询真实就绪标志（`window.__app` + 具体元素存在），最多等 15 秒。另外**残留的旧实例**会占着调试端口，让测试连到上一版（可能已坏的）程序上 —— 报出的错误跟刚编译的代码毫无关系。所以 build.ps1 在**编译前**先清理残留进程 |
| 78 | 残留实例会锁住编译产物 | 上一轮测试留下的 `kts-builder.exe` 还在跑，Windows 就锁着这个文件，`cargo build` 会以一句极难懂的话失败：`error: failed to remove file '...\target\release\kts-builder.exe'`。<br>清理必须放在**编译之前** —— 放编译之后毫无用处，那时构建已经失败了。这个教训是实际踩到的：我第一版把清理加在第 6 步（因为假失败发生在那里），结果紧接着的构建就在第 3 步挂了 |
| 79 | build.ps1 必须纯 ASCII | `build.ps1` 走 Windows PowerShell 5.1，它**按 ANSI 代码页**解析 `.ps1`（不是 UTF-8）。里面一旦出现中文注释就是乱码字节，轻则报错、重则把后面的语法结构吃掉。我自己就犯过：给 `log-unit.js` 加注释时顺手写了「按钮: fit」。文件仍是合法 PS 脚本、单独跑也看不出来 —— 只在别的机器/代码页上炸。`tests/encoding.js` 第 5 组在**字节层面**查这个（并已实测：往 build.ps1 里加一句中文注释，它立刻报错） |

### 4.2 控件定义（Catalog Def）

```js
{
  key: "action.applyStatus",          // 唯一键，也是锚点里的 kind
  category: "action",                 // event|action|condition|data|loop|timer|query
  label: "给单位加状态",               // 场景化中文名（人话）
  terms: "applyEffect StatusEffects 单位 状态 减速",  // 搜索关键词（代码模式显示用）
  codeHint: "unit.apply(StatusEffects.x, 秒*60f)",
  inPorts:  [{ id: "in", type: "flow" }],
  outPorts: [{ id: "out", type: "flow" }],
  props: [
    { key: "unit",  type: "unitRef", label: "目标单位", required: true, default: "$unit" },
    { key: "status", type: "select", label: "状态", required: true,
      options: [["slow","减速"],["unmoving","无法移动"],["electrified","通电"], ...] },
    { key: "seconds", type: "number", label: "持续秒数", required: true, default: 5, min: 0.1 }
  ],
  contexts: [],                       // 该节点为下游提供的变量（如 query/loop 提供列表项）
  emit: (n, ctx) => [`${ctx.expr(n.props.unit)}.apply(StatusEffects.${n.props.status}, ${n.props.seconds}f * 60f)`]
}
```

`emit` 返回**该节点自身**的代码行（不含子树）；子树的缩进由生成器统一处理。

### 4.3 端口类型系统

| 类型 | 含义 | 来源 | 可连入 |
|------|------|------|--------|
| `flow` | 执行流 | 事件/动作/条件/循环/定时/指令 | flow 入端口 |
| `Unit` | 单个单位 | 事件上下文、循环项 | unitRef 参数 |
| `UnitList` | 单位列表 | 查询控件 | forEach 循环 |
| `Player` | 玩家 | 事件上下文、指令上下文 | playerRef 参数 |
| `Team` | 队伍 | 事件上下文 | teamRef 参数 |
| `Tile` | 地块 | 点击方块事件 | tileRef 参数 |
| `Number` / `String` / `Boolean` | 值 | 数据控件、上游字段 | 对应参数 |

**强类型约束**：连线时校验 `fromPort.type` 是否可赋给 `toPort.type`（`flow→flow`，其余精确匹配或子类型）。不匹配则连线弹回并在状态栏说明原因（"这里需要『单位』，你给的是『玩家』"）。

### 4.4 连线与嵌套规则（含一处需要你确认的取舍）

- **结构线（flow）**：从上游出端口拉到下游入端口，表示"下游写进上游的花括号里"。
- **出线**：不限制条数（一个事件可以带多个动作）。
- **入线**：默认唯一。拖第二条结构入线 → **替换**旧的（可 Ctrl+Z 撤销）。
- **按住 Shift 拖入** → 记为**引用线**（`kind: "ref"`）：不产生嵌套，只表示"该节点产出的变量可在下游使用"。
- **禁环**：连线前做 DFS，若形成环则拒绝并提示"A 已经在 B 里面了，不能再连回去"。
- **多入线的兜底**（针对导入/手改工程文件）：按固定优先级 `condition > loop > timer > event > command > root` 选出唯一嵌套父，其余入线自动降级为引用线，并在状态栏给出警告。

> **需要你确认**：选项 6 的表述（"每个控件最多一条入线"）与选项 7 的表述（"多入线用固定优先级"）严格说互相矛盾。我按"**结构入线唯一 + 多入线兜底降级**"实现，这同时满足"禁环"与"确定性"，且小白不会遇到歧义。若你要的是"允许多条结构入线并按优先级真的嵌套多层"，告诉我，我改成真多父实现。

- **同级顺序**：同一父节点下的子节点，按 `(y, x)` 升序（上→下，同 Y 左→右）。
- **多输出槽**：条件控件有 `then` / `else` 两个出端口，分别对应 `if {}` 与 `else {}`。

### 5.2 动作控件（10 个）

| `kind` | 界面显示 | 参数 | 生成代码 |
|--------|----------|------|----------|
| `action.broadcast` | 发消息 / 全服广播 | 目标（全服/指定玩家）、内容模板、显示方式、是否静默 | `broadcast("[green]文本".with(...), MsgType.InfoMessage, 10f, quite = false)` / `player.sendMessage(...)` |
| `action.applyStatus` | 给单位加状态 | 目标单位、状态、秒数 | `unit.apply(StatusEffects.unmoving, 5f * 60f)` |
| `action.spawnUnit` | 生成单位 | 单位类型、队伍、位置 | `UnitTypes.mono.spawn(Team.sharded, x, y)` |
| `action.giveItem` | 给物品 / 资源 | 目标核心、物品、数量 | `player.team().data().core()?.items?.add(Items.copper, 100)` |
| `action.setRule` | 修改游戏规则 | 规则项、值 | `state.rules.fire = false` |
| `action.effect` | 播放特效 / 标记 | 特效名、位置、颜色 / 文本标记 | `Call.effect(Fx.placeBlock, x, y, 0f, Color.red)` / `Call.label("[yellow]文本", 5f, x, y)` |
| `action.playerControl` | 踢出 / 换队玩家 | 目标玩家、操作（踢出/换队/清空单位） | `player.kick("[red]原因", 0)` / `player.team(Team.sharded)` |
| `action.delayed` | 延时后执行 | 毫秒数 | `launch(Dispatchers.game) { delay(3000L); ... }`（**带子节点槽**） |
| `action.registerCommand` | 注册指令 | 名字、说明、别名、权限、仅玩家可用 | `command("hi", "说明") { ... }`（**带子节点槽**，根节点） |
| `action.savable` | 记住数据 / 存盘 | 变量名、类型、初值 | `@Savable var x = 0` + `customLoad(::x) { x = it }`（**根节点**） |

说明：
- 位置参数统一提供 4 种来源：`玩家位置` / `单位位置` / `方块位置` / `固定坐标(x, y)`。
- `action.registerCommand` 内部的子节点里，"当前玩家"解析为 `player!!` 并在勾选"仅玩家可用"时生成 `attr(ClientOnly)`；未勾选时生成 `player?.let { ... }` 保护。
- `action.savable` 支持类型 `Int / Long / String / Boolean / List<String> / MutableMap<String,String>`，后者按工作区惯例生成 `customLoad(::x) { x.putAll(it) }`。

### 5.3 条件控件（1 个，带 then/else 两槽）

```
condition.if    「如果……就」
```

- 条件由 1..n 条规则组成，规则之间用 `且` / `或` 连接，支持括号分组（一层）。
- 每条规则 = `对象字段` + `比较运算符` + `值`。

字段选择器基于 §6 的类型字段表：选了"上游的玩家"就只列出 Player 的字段。

生成：

```kotlin
if (player.dead() || player.admin) {
    // then 子节点
} else {
    // else 子节点（可为空）
}
```

运算符：`等于 / 不等于 / 大于 / 小于 / 大于等于 / 小于等于`。
布尔字段（如 `player.dead()`）走"真/假"选择，不出现运算符。

### 5.4 数据控件（1 个）

```
data.value      「记住一个值」
```

- 值来源：`固定文本` / `数字` / `真或假` / `上游字段` / `坐标` / `当前时间`
- 生成：`val <名字> = <表达式>`
- 名字校验：必须是合法 Kotlin 标识符、同一画布内不重复、不与上下文变量同名。

### 5.5 循环控件（1 个，两种模式）

```
loop.repeat     「重复 N 次」            -> repeat(5) { ... }
loop.forEach    「对每个单位做」          -> targets.forEach { unit -> ... }
```

`loop.forEach` 的列表来源：查询控件的输出，或事件上下文里的列表。
`loop.forEach` 产出变量 `unit`（名字可改），供内部子节点使用。

### 5.6 定时控件（1 个）

```
timer.every     「每隔 X 秒」
```

- 参数：间隔（秒/毫秒）、是否用真实时间（默认游戏时间）
- 可作根节点（脚本启用就开始跑），也可挂在事件下（事件触发才开始跑）
- 生成：

```kotlin
loop(Dispatchers.game) {
    delay(30_000L)
    // 子节点
}
```

> 依据：`loop` = `Script.loop(context, block)`，内部 `while(true)` + 捕异常 + 睡 10 秒；脚本禁用时随协程作用域自动停止。

### 5.7 查询控件（1 个）

```
query.units     「找出符合条件的单位」
```

- 参数：所属（全部/敌方/己方/指定队伍）、附加条件（复用 §5.3 的规则编辑器）
- 产出变量：`targets`（`UnitList`），可被 `loop.forEach` 使用
- 生成：

```kotlin
val targets = Groups.unit.filter { it.team == state.rules.waveTeam && it.type.flying }
```

## 7. 代码生成规则

> **⚠ 本节里的文件骨架已过时。** 实际生成的文件**没有文件头注释**（`module.kts` 里一条注释都没有），
> 每个控件的锚点写成一行的 `//@<控件编码> <x> <y> [嵌套层级]` 并**顶格**（不再缩进）。
> 实际例子见[使用手册](../使用手册.md)的「导出的代码长什么样」。下面保留原文以记录取舍过程。

### 7.1 文件骨架

```kotlin

<按 (y,x) 排序的根节点，逐个递归生成>
```

- 锚点行是 Kotlin 合法注释，不影响运行。
- `module.kts` 单独生成：


- 若模块勾选了额外依赖（如 `wayzer/maps`、`coreLibrary/db`），追加对应 `@file:Depends` 行。

### 7.2 递归生成算法

```
generateCanvas(canvas):
  roots = nodes where no structural in-edge
  roots.sortBy(y, x)
  out = []
  for r in roots: emit(r, depth=0)
  return out.join("\n")

emit(node, depth):
  ind = "    " * depth
  lines = [
    ind + anchorComment(node),
    ...def.emit(node, ctx).map(l => ind + l),   # 头部行（含未闭合的 { ）
  ]
  for port in def.outPorts:
     children = structuralChildren(node, port).sortBy(y, x)
     for c in children:
        lines += emit(c, depth + 1)
     if port 需要闭合: lines += ind + closingFor(port, node, ctx)   # 如 "}"
  return lines
```

关键点：
- **未闭合括号**由 `def.emit` 负责开、由 `closingFor` 负责关；`else` 槽在 `then` 闭合后输出 `} else {`。
- 上下文变量作用域：节点产出的变量（`loop.forEach` 的 `unit`）在其子树内可见；生成时维护 `ctx.vars` 栈。
- 未使用的上下文绑定会自动省略（避免生成 `val team = it.team` 却没人用）。

## 8. 校验规则（轻量结构校验，无编译器）

**错误（阻断导出）**

| 规则 | 提示文案 |
|------|----------|
| 必填参数为空 | 「`给单位加状态` 还没选『状态』」 |
| 端口类型不匹配 | 「`发消息` 需要『玩家』，但上游给的是『地块』」 |
| 存在环 | 「`条件` 已经在 `发消息` 里面了，不能再连回去」 |
| 动作引用的变量不存在 | 「用了『目标单位』，但这条链上没有单位来源」 |
| `repeat` 次数 ≤ 0 或非整数 | 「重复次数要是大于 0 的整数」 |
| 延时/间隔 ≤ 0 | 「间隔要大于 0」 |
| 变量名非法或重复 | 「同一画布里有两个都叫 `count` 的值」 |
| 指令名含空格或重复 | 「指令名不能有空格」「两个画布都注册了 `hello`」 |
| 画布文件名为空/非法 | 「文件名只能用字母、数字、下划线」 |
| 未知控件类型（导入坏工程） | 「不认识这个功能块：`action.xxx`」 |

**警告（放行）**

| 规则 | 提示文案 |
|------|----------|
| 事件没有任何下游动作 | 「『玩家进服』后面还没有要做的事」 |
| 画布为空 | 「这张画布是空的，导出后会是个空文件」 |
| 模板里用了未注册的变量 | 「`{player.hp}` 可能不存在，确认一下（`Player` 没有这个字段）」 |
| 引用了当前模块未声明的脚本依赖 | 「用了 `Groups.unit` 之外的东西，可能需要加依赖」 |
| 条件恒真/恒假（两侧类型不可能相等） | 「这个条件永远不成立，检查一下」 |
| 未被使用的数据控件 | 「`count` 定义了但没人用」 |

**校验时机**：每次模型变更后立即重算（防抖 200ms），结果写入状态栏；导出时若有 error 则弹出清单并禁止导出。

## 11. 导出流程

> **实现时的修订**：工具最终是 **Tauri 桌面 exe**（不是网页），所以导出不再是"下载 ZIP"，而是**直接写进你选的目录**；ZIP 打包作为备用路径保留（`zip.js` 仍在，供无 Tauri 环境时用）。

```
1. 点「导出插件」
2. 有 error → 弹出问题清单，禁止导出；只有 warning → 提示后可继续
3. 生成内存中的文件表：
     demo/module.kts
     demo/welcome.kts
     demo/alert.kts
4. 弹出原生文件夹选择框（COM IFileDialog）
5. 直接写盘：<选的目录>/demo/module.kts 等
   —— Rust 侧先逐项校验相对路径（拒绝绝对路径/UNC/盘符/../ADS/NUL/非法字符），
      再"全写或全不写"，避免导出到一半留下半个插件
6. 弹 toast 告知写了几个文件，可点「在资源管理器里打开」
7. 把 demo/ 整个丢进 Mindustry 的 scripts/ 目录，服务端执行 /sa scan（这一步工具不管）
```

导出内容**不包含** `.metadata`、`plugin.json`（依你的选择）。
`zip.js` 仍保留：在**没有 Tauri 环境**时（浏览器里打开 `src/frontend/` 调试）导出会自动退回「下载 ZIP」路径，因为在网页里没法直接写盘。桌面版走的是上面的目录写入，没有单独的 ZIP 按钮。

## 12. 反向解析（锚点往返）

> **⚠ 本节已过时（锚点格式 v1 的设计稿）。** 实际实现见 `src/frontend/js/anchor.js`：
> 锚点格式已改为紧凑的 `//@<控件编码> <x> <y> [嵌套层级]`，**不再写 `id` / `module` / `title`**，
> 嵌套关系也从「缩进层级」改成锚点里显式的**层级数字**（锚点一律顶格）。
> 老格式（本节描述的 `// @sa:` 写法）仍然能被解析，用户已有的 `.kts` 不会报废。
> 下面保留原文只为记录当时的取舍。

- **写**：生成时每个节点/文件写一行锚点注释，含 `id`、`def`、`x`、`y`、`module`、`title`。
- **读**：`anchor.js` 用正则扫描文件 → 还原节点与坐标。父子的嵌套关系从**缩进层级**恢复；同缩进的按出现顺序还原为同级（并回填 y 让它重排后顺序不变）。
- **一致性检查**：还原后重新生成一遍，与原文去掉锚点后的代码比对；不一致则提示"这个文件被手工改过，只恢复了能认出的部分"，并保持画布不变（依你选的"手动触发回解 + 只读预览"）。
- **局限（已知并接受）**：手写的、没有锚点的 `.kts` 无法解析；解析失败时给出第一处无法识别的位置。
