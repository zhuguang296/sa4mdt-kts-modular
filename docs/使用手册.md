## 一、这是什么，不是什么

**是什么**

一个可视化的 `.kts` 脚本编辑器。你在画布上拖方块、把它们连起来、在右边填参数，工具把这些拼成一段能直接放进服务器的 Kotlin 代码，导出成 `.kts` 文件。

**不是什么**

工具**完全不碰**生成出来的代码。它：

- **不执行** —— 不会跑你搭的逻辑
- **不加载** —— 不会把 `.kts` 读进游戏
- **不编译** —— 没有 Kotlin 编译器，做的是结构校验，不是真编译
- **不热重载** —— 改完必须自己导出、自己放进服务器

也就是说：**导出成功 ≠ 代码一定能用**。工具能保证括号配平、必填项填了、名字不冲突，但生成的东西到底能不能在游戏里跑起来，得你放进服务器用 `/sa scan` 加载一次才知道。

工具的定位就是「写」这一段：把「记住 API 长什么样」这件事从你脑子里挪到界面上。运行、调试、看日志，都还是游戏那边的事。

## 二、五分钟上手

1. 双击 `KTS-Plugin-Workshop.exe`（或从开始菜单启动装好的版本）。
2. 启动后是**主界面（首页）**，点一个已有的插件组进去，或者点 **＋ 新建插件组** 建一个。
3. 进了画布，点工具栏 **套用模板**，随便挑一个（比如「进服欢迎」）。
4. 画布上出现几个方块和连线 —— 这就是一个能用的插件了。
5. 点方块，右边改参数（比如把欢迎语改成你想说的话）。
6. 点右上角 **代码预览**，看一眼将要生成的 Kotlin 代码。
7. 点 **导出插件**，选一个目录。
8. 把导出的整个文件夹（例如 `demo/`）复制到服务器的 `scripts/` 目录下，在游戏里执行 `/sa scan`。

想从零开始而不是套模板，就看下一节。

### 从零搭一个

1. 工具栏 **新建** → 填插件名 / 作者 / 模块名（也就是插件组名，见[第四节](#四主界面首页)）。
2. 从左边「入门」里拖一个 **当……发生时**（事件控件，比如「玩家进服」）到画布。
3. 再拖一个 **要做的事**（动作控件，比如「发消息」）进来。
4. 把事件右边的小圆点拖到动作左边的小圆点上 —— 这条线表示「这段代码写在那个花括号里」。
5. 点中动作方块，在右边把参数填好。
6. 看右下角状态栏：`0 个错误` 就可以导出了。

工具栏的 **怎么用** 按钮里也写着这套步骤。

## 三、安装与启动

两种方式，按喜好挑：

### 安装包（推荐）

`KTS-Plugin-Workshop_<版本>_x64-setup.exe`（约 1.1 MB）。装完有开始菜单快捷方式和卸载项，默认装到 `%LOCALAPPDATA%\KTS-Plugin-Workshop`，**不需要管理员权限**。

### 免安装

项目根目录的 `KTS-Plugin-Workshop.exe`（约 3.3 MB），双击即用。

> 工具界面是**中文**的（按钮、菜单、控件名都是中文），英文名 `KTS-Plugin-Workshop` 只用于发行文件、安装目录和开始菜单项。

两个都**不需要 Java、不需要 Node**。

> 发行版 exe 和安装包不放在仓库里，请到 GitHub Releases 页面下载。从源码构建和打安装包的方法见根目录 `README.md`。

### 启动后

一打开就是**主界面（首页）**，列出所有**插件组（旧称模块）**，四个入口：

| 入口 | 做什么 |
|---|---|
| **打开工程** | 继续之前的 `.saproj` 工程文件 |
| **从代码还原** | 把本工具导出的 `.kts` 还原成画布 |
| **新建工程** | 填插件名 / 作者 / 模块名，从空白画布开始 |
| **设置** | 界面、画布、导出等偏好设置 |

点列表里的某个插件组就进入它的画布。详细说明见[第四节](#四主界面首页)。

> 以前启动时弹的那个「新建 / 打开 / 模板」欢迎弹窗**已经删掉了** —— 那三件事现在都归首页管，而且首页能一眼看到所有插件组。套用模板仍然是画布工具栏上的一个按钮。

## 四、主界面（首页）

**主界面就是首页** —— 启动时直接进来，工具栏上的 **主页** 按钮随时能回到这里。
它的职责很单一：**选一个插件组开工**。画布只负责「编这一个插件组」，两件事分开。

### 插件组是什么

**插件组（旧称模块）** 导出一个目录，里面有 `module.kts` 和它下面每张画布生成的脚本。
两个词指的是同一个东西；界面和首页上现在统一叫**插件组**，工具栏上的按钮仍叫「新建模块 / 模块管理」。

首页列出所有插件组，每个卡片上写着它的规模：

```
插件组
2 个 · 每个插件组导出后是一个独立文件夹
┌────────────────────────────────────────────────────────────┐
│ shop                                          上次编辑     │
│ 3 个画布 · 12 个控件 · 9 条连线 · main.kts      [改名][删除]│
├────────────────────────────────────────────────────────────┤
│ arena                                                      │
│ 1 个画布 · 4 个控件 · 3 条连线 · welcome.kts     [改名][删除]│
└────────────────────────────────────────────────────────────┘
[＋ 新建插件组]
```

- **画布数 / 控件数 / 连线数 / 主文件名** —— 卡片第二行。控件数和连线数是这个插件组下**所有画布相加**的。
- **上次编辑** —— 最近编辑过的那个插件组（也就是当前画布所属的那个）会被标出来。标签栏里的副标题用的是 `.kts` 文件名，跟这里的主文件名是同一个。
- **点卡片** —— 进入它的画布（切到该组的第一个画布）。
- **改名 / 删除** —— 卡片右侧的两个小按钮。点它们**不会**顺带进入画布。
  - **改名**：新名字会成为导出后的文件夹名，也是脚本的包名（只能用字母、数字、下划线）。
  - **删除**：会问一次确认，且可以 `Ctrl+Z` 撤销。**只剩一个插件组时删除按钮不出现** —— 整个插件至少要有一个插件组。

### 新建插件组

点 **＋ 新建插件组**，就地展开一个输入框（不弹对话框）：

1. 填插件组名字（例如 `shop`）。只能用字母、数字、下划线 —— 导出后会变成同名文件夹。
2. 点 **创建**（或按回车）。

> 建完之后**留在首页**，新插件组直接出现在列表里 —— 这是有意为之：
> 你往往要连着建好几个，跳进画布反而碍事。想进它，点那张卡片就行。

### 顶部四个入口

| 按钮 | 作用 |
|---|---|
| **打开工程** | 打开一个 `.saproj` 工程文件 |
| **从代码还原** | 把本工具导出过的 `.kts` 还原成画布（见[第十一节](#十一从代码导入还原回画布)） |
| **新建工程** | 填插件名 / 作者 / 模块名，换成一个全新工程（仍留在首页） |
| **设置** | 打开设置页（见[第十二节](#十二设置)） |

### 回到首页

画布工具栏最左边就是 **主页** 按钮，点了就回到这个列表。插件组的改动（新建、改名、删除）会实时反映在列表上。

## 五、界面总览

```
┌─────────────────────────────────────────────────────────────┐
│ 工具栏：主页 │ 新建 打开 保存 │ 套用模板 新建模块 模块管理    │
│        ↶ ↷ │ − 适应 + │ 从代码还原 怎么用 全屏 设置 │ 预览 导出│
├──────────┬───────────────────────────────┬──────────────────┤
│ 控件库   │ 画布标签页                    │ 参数面板         │
│ （两列） │                               │                  │
│ 入门     │      画 布                    │  所选控件的表单   │
│  当……发生时│                              │                  │
│  交互    │                               │                  │
│  服务器  │                               │                  │
│ 高级     │                               │                  │
│  ...     │                               │                  │
├──────────┴───────────────────────────────┴──────────────────┤
│ 状态栏：N 个文件 · N 个错误 · N 个提醒 · 未导出   ● 未保存  100% │
└─────────────────────────────────────────────────────────────┘
```

- **左侧控件库**：比 1.1.0 更宽（**300px**），每个分类下的控件按**两列**排布，一次能看到的控件更多。按分类折叠（像积木编程，用什么点什么）。**每次启动都是全折叠** —— 展开状态不记忆，避免上次点开过的分类在下次启动时全敞着。搜索框里打字时自动平铺所有命中项（同样是两列），并强制展开。
- **中间画布**：一张画布 = 一个 `.kts` 文件。
- **右侧参数面板**：显示当前选中控件的表单；没选中时是一句提示。
- **状态栏**（右下角）：`已生成 N 个文件 · N 个错误 · N 个提醒 · 未导出`，加上「● 未保存 / ✓ 已保存」标记、当前缩放百分比、以及「查看问题」按钮（有问题时点亮，点开是完整问题清单）。
- **代码预览**（工具栏右上）：弹窗显示这张画布会生成的全部代码，深色高亮、只读、可复制。

## 六、画布操作

### 加控件

从左侧控件库**拖**到画布上。**只有拖，没有双击。**

拖动时会有一个半透明的「幽灵卡片」跟着鼠标，落点处会提前显示一张卡片的虚影，让你知道会放在哪。

拖进来的控件会自动选中，右边参数面板立刻显示它的表单。

### 缩放

滚轮，任何时候都生效，**以鼠标位置为中心** —— 光标底下的那个点不会跑。范围 **25% ~ 250%**。

每滚一格缩放多少可以在设置里调（「滚轮缩放灵敏度」，默认 10%）。工具栏的 `−` / `+` 按钮也能缩放，`适应` 按钮让所有方块都显示出来。

右下角状态栏一直显示当前缩放比例。

### 平移

- **左键拖动空白处**（主方式）
- 右键拖动
- 中键拖动
- 空格按住 + 左键拖动
- `Alt` + 左键拖动

右击空白处**不会**弹菜单 —— 右键是平移手势，弹菜单会和它打架。

### 拖动控件

左键拖方块本身即可。拖动过程中吸附默认**不**生效（不然鼠标会有「被格点拽着走」的黏滞感），松手时才卡到最近的格点（如果开了「拖动时吸附对齐」）。

### 多选与删除

- 按住 `Ctrl`（或 `Shift`）逐个点节点来多选。再点一次已选中的节点会把它取消选中。
- 选中后按 `Delete` 或 `Backspace` 删除。
- 每个方块右上角也有一个 **×**，点它删掉这一个。

### 网格

设置里可以开「显示背景网格」（**默认关**），并调网格间距（8~100px，默认 20）。放大画布时网格会跟着一起放大。

## 七、连线

**连线表示「包含」**：一个动作连在事件后面，就表示这段代码写在事件的花括号里。

### 怎么连

把上一个控件**右边的小圆点**拖到下一个控件**左边的小圆点**上。反过来从入口往出口拖也行。

拖动时鼠标附近的合法落点会变色提示：绿色可以连，红色不行，并且右下角会弹一句说明为什么不行。

### 连线规则

工具会替你挡掉这些明显会出事的连法：

- **不能连到自己**
- **只有「执行」类型的接口可以连线**（数据类的接口不参与）
- **起点控件不能接在别的控件后面**（比如事件控件后面不能再接事件）
- **不能绕成死循环** —— 会提示「已经在……里面了，连回去会绕成死循环」
- **一个入口只能有一条入线** —— 给已经有入线的入口再连一条，旧的会被替换掉（可以 `Ctrl+Z` 撤销）

### 条件控件的两个出口

`如果……就` 和 `如果是管理员` 有**两个出口**：**就**（then）和**否则**（else）。从不同的小圆点拖出去，就会分别生成 `if (...) { }` 和 `else { }` 两块。

`不满足就跳过（提前退出）` 也有两个出口：「满足时继续」和「不满足时」。

### 删连线

**鼠标移到连线上**，线的中点会浮出一个 **×**，点它删掉那一条。可以 `Ctrl+Z` 撤销。

### 删掉一个控件的全部连线

在节点上**右键单击**，菜单里选「断开所有连线（N 条）」。没有连线时这一项是灰的。

注意：右键**拖动**仍然是平移画布 —— 只有「按下去没动就松开」才弹菜单。

一次「断开所有连线」只记一个撤销点，按一次 `Ctrl+Z` 就整批恢复，不用一条条往回退。

## 八、参数面板

选中一个控件后，右侧面板从上到下是：

1. **分类和控件名** —— 例如「要做的事 / 发消息」。
2. **代码长什么样** —— 这个控件大致会生成哪一行 Kotlin，让你心里有数。
3. **说明**（如果这个控件有的话）—— 使用注意事项。
4. **这个事件带给你的变量**（只有事件控件有）—— 比如「玩家进服」会给你一个 `player`。这些变量可以在这条链后面所有控件的表单里直接引用。
5. **设置** —— 这个控件的参数表单。

### 表单里的字段类型

| 类型 | 长什么样 | 说明 |
|---|---|---|
| 文本 | 单行输入框 | 带 `*` 的是必填 |
| 多行文本 | 文本框 | 消息类控件用它，下面有「可插入：{player} {message}」变量按钮，点一下就把变量名插到光标处 |
| 数字 | 数字输入框 | 只接受数值；填非数字会报错 |
| 下拉 | 选择框 | 选项都是核对过的；个别标着「未验证」表示来源不确定 |
| 开关 | 左右滑动的小开关 | 真 / 假 |
| 条件规则 | 一组「判断谁 / 判断什么 / 怎么比 / 跟什么比」 | 见下 |

有些字段是**联动**的：选了 A 才出现 B。比如「记住一个值」里「值从哪来」选了「写一个数字」，才会出现「值」这一栏。

### 指令的「冷却（秒，0 = 不限）」

**1.2.0 新增**：「做一个服务器指令」多了一个 **冷却（秒，0 = 不限）** 参数，默认 `0`。

| 填什么 | 效果 |
|---|---|
| `0`（默认） | 不限制，生成的指令和以前一样 |
| 大于 0 的数 | 生成的指令体会先做一次冷却检查：同一个人在这个秒数内重复用会被挡下来，并回一句「冷却中，请稍后再试」 |

计时是**按玩家分别记**的（一人一份），所以一个人进冷却不影响别人。这个参数只是往指令体开头加了一段检查，**指令的出口没有变化** —— 仍然只有一个出口，后面的连线照旧。

### 条件规则编辑器

`如果……就` 这类控件用的是规则编辑器：

- 一行一条规则，从左到右依次选：**判断谁**（上游的哪个变量）→ **判断什么**（它的哪个属性）→ **怎么比**（等于 / 大于……）→ **跟什么比**（填一个值，或者用另一个变量）。
- 如果选的属性本身就是「真 / 假」（比如「是管理员」），那就没有比较运算符这一栏 —— 它本身就是判断条件。
- 有些属性需要一个参数（比如「包含文字」要填要包含什么、「拥有权限」要填权限名），会多出一个输入框。
- 点 **+ 添加一个条件** 加一条，点规则右边的 **×** 删一条。
- 有两条以上时会出现「上面这些条件」：**要全部满足**（并且）/ **满足任意一个就行**（或者）。

> 如果这块提示「这条链上还没有任何可判断的东西」，说明这个条件控件没有接在事件（或其它带来变量的控件）后面。条件要靠上游的变量才能判断。

### 一个常见困惑：变量在哪儿选

条件控件、数据控件里能选的变量，来自**这条链上游** —— 也就是从起点沿着连线一路走到你这里，路上声明过的东西。所以：

- 直接把条件拖到画布上、不连线，它会说没有可判断的东西。
- 把条件接在「玩家进服」后面，就能判断 `player`。
- 在条件里面再接一个「记住一个值」，那个新变量只在条件内部可见。

## 九、校验：错误与提醒

工具一直在后台校验整个工程（每次改动都会重算），结果分两类：

| | 错误 | 提醒 |
|---|---|---|
| 图标 | ✕ | ! |
| 会阻止导出吗 | **会** | 不会 |
| 例子 | 必填项没填、模块名不合法、两个画布重名、注册了两个同名指令 | 画布是空的、事件后面还没接动作、控件名字和系统内置的重名、模块少了依赖 |

**清单里的每一条都可以点** —— 点它会自动切到那张画布、选中那个出问题的控件，直接就能改。问题不在当前画布时会自动跳过去。

一个常见例子：`「发消息」的「说点什么」还没填`。填上就好了。

### 错误必须清零才能导出

点「导出插件」时如果还有错误，会弹出问题清单并中止导出。

有提醒但不阻止导出时，会问一句「还有 N 条提醒，这些提醒不影响导出，确定继续吗？」。

> 校验是**结构校验**（括号/引号配平、必填项、重名、名字合法性），不是真编译。工具还会对自己生成的代码做一次括号配平自检 —— 万一配平出问题（那是工具的 bug），也会当成错误报出来。

## 十一、从代码导入（还原回画布）

工具栏 **从代码还原**，选一个 `.kts` 文件，工具会把它解析回一张画布，追加到**当前插件组**下（`Ctrl+Z` 可撤销）。

用途：别人发给你一个用本工具导出的 `.kts`，你想接着改，不用从零重搭。

### 怎么判断一个文件能不能还原

解析器靠的是工具写在代码里的**锚点注释**（就是那些 `//@...` 的行）。如果选的文件里没有这种注释，会直接提示：

> 这个 .kts 文件里没有本工具留下的标记，无法还原成画布

### 能还原什么

- **控件的位置** —— 锚点里存了画布坐标。
- **控件的嵌套关系** —— 锚点里存了层级数字，据此重建父子连线。
- **控件是哪个** —— 存的是控件编码，查表就能认回来。

还原出来的画布会加到**当前插件组**下，并自动切过去。它的：
- **画布名（标签上显示的中文名）** 固定是「导入的画布」
- **文件名** 取自你选的那个 `.kts` 的文件名（比如选 `welcome.kts`，就还原成 `welcome`）

### 还原不了什么（这几条很重要）

1. **表单参数不会还原。** 参数没有写进注释里 —— 注释里只有「哪个控件、在哪儿、嵌套几层」。所以还原出来的每个控件都是**空壳**，参数要你重新填一遍。

   还原成功后工具会明确提示：
   > 只还原了功能块的位置和嵌套关系，具体填的参数需要你重新确认（导出的文件里没有保存表单内容）

2. **画布名不会还原。** 为了把注释压到最小，画布标题没有存进锚点。还原出来的画布标签一律叫「**导入的画布**」，文件名则取自你选的那个 `.kts`。想改名字就双击标签重命名（见[第十五节](#十五插件组与画布管理)）。

3. **手写的 `.kts` 不保证能还原。** 「从代码还原」只认自己导出的文件。手写的代码里没有锚点，还原不了。

4. **条件控件的 then/else 靠顺序推断。** 锚点里没有记「这个子节点挂在`就`还是`否则`上」，解析器是按子节点的出现顺序依次分给两个出口的。正常画布上（`就`的子节点排在前、`否则`的排在后）结果正确；但如果一个条件下面挂了三个以上子节点，分派结果可能和你想的不一样 —— 自己核对一下这块。

5. **认不出的控件会被跳过，但工具会告诉你。** 如果 `.kts` 里有锚点但控件名对不上（比如新版本删掉的控件），那一个会被跳过，别的照常还原。还原完的提示里会写明「有 N 个功能块这个版本认不出、已跳过」—— 不会让你只看到「还原出 3 个」却不知道文件里本来是 5 个。

6. **节点 id 会重新分配。** 所以同一个文件连导两次也不会和已有的画布撞 id，可以放心重复导入。

### 老版本文件仍然能导入

**1.1.0 及更早版本**导出的文件用的是老格式（`// @sa:file id=... module=... title=...` / `// @sa:node id=... def=... x=... y=...`）。这种文件**仍然可以正常还原** —— 工具同时认两套格式，这条有回归测试（`tests/anchor.js`）盯着。

如果想在本工具里试试，工具栏的 **代码预览** 弹窗底部也有一个「从代码还原画布」按钮。

## 十三、日志

日志**默认开启**，写在 **exe 旁边的 `logs\` 文件夹**里，按天分文件：

```
logs\kts-builder-2026-09-27.txt
```

具体的完整路径在设置页的「日志」分类里显示（「当前日志文件」那一项），点「打开日志文件夹」也能直接跳过去。

### 记这些内容

- **错误与警告** —— **逐条**列出，带是哪个插件组、哪个画布、哪个控件。不是只写「3 个错误」—— 那种记录过两天回头看等于没记。
- **耗时** —— 每个按钮响应了多少毫秒，以及保存 / 导出 / 还原这些关键操作内部花了多久。你说「点了要等好久」时，日志里那一行就直接指出来了。
- **崩溃** —— 完整堆栈 + **当时的工程规模**（N 个插件组 / N 个画布 / N 个控件 / N 条连线）+ **崩溃前 40 步操作轨迹**。光有堆栈只知道崩在哪；有了这两样才知道你当时在编辑多大的工程、崩溃前点了什么。
- **启动与关闭** —— 版本、时间、WebView2 环境。

崩溃写进**同一个文件**（不再单独出 `crash.log`），所以排查时不用在两处对时间。

### 特意不记什么

**不记录生成的 Kotlin 代码。** 那种内容又长又占地方，而且代码是「画布 + 参数」推出来的 —— 这两样本身已经在别的记录里了。这个决定是有意的：日志是拿来定位问题的，不是拿来存代码的。

操作轨迹（你点了哪些按钮）平时只在**内存**里转，**不落盘** —— 否则每次点按钮都要多写一行，平时就把日志撑肿了。只有真出错时才跟着崩溃记录一起写出来。

### 怎么看

设置里切到「日志」页就能直接看今天日志的末尾，还有四个按钮：

- **刷新**
- **打开日志文件夹**
- **复制全部** —— 反馈问题时把这段贴过来就够了
- **清空今天的日志**（红色，谨慎点）

### 出问题时

工具里任何没被接住的错误都会：

1. 在右下角弹一个**看得懂**的提示框（不是一堆英文堆栈）；
2. 把完整信息写进上面的日志文件；
3. 提示框里直接显示日志路径。

提示框上的按钮：**关掉提示继续用** / **另存工程** / **复制详细信息** / **隐藏** / **打开日志文件夹**。

所以即使某个功能坏了，你的画布内容也还在，能把进度存下来再重启。同一个错误最多提示 3 次，不会刷屏把界面盖死。

**反馈问题时把日志文件发过来就够了**，不用描述「我点了哪个按钮」。

## 十五、插件组与画布管理

### 插件组（旧称模块）

一个**插件组**（也就是以前的「**模块**」，界面和首页上现在统一叫插件组）导出后就是一个目录，里面有 `module.kts` 和这个插件组下所有画布生成的脚本。

- 在[首页](#四主界面首页)点 **＋ 新建插件组**，或在画布工具栏点 **新建模块**：填名字，勾依赖。名字会成为目录名，也是脚本的包名 —— 只能用字母、数字、下划线。
- 在[首页](#四主界面首页)可以直接**改名 / 删除**一个插件组；画布工具栏的 **模块管理** 则列出当前所有插件组（名字、依赖、画布数），可以在这里删除。

可选的依赖：`coreMindustry`（推荐，带来玩家/单位/方块等一切）、`coreLibrary`（基础库）、`wayzer`（管理功能）、`mapScript`（地图脚本）、`coreLibrary/extApi/KVStore`（键值存储）。

删除插件组前会问一次确认，并且这个操作可以 `Ctrl+Z` 撤销。**只剩一个插件组时删除按钮是禁用/不出现的** —— 整个插件至少要有一个插件组，否则导出没有目录可建。

> 如果某个控件需要额外依赖而插件组里没声明，校验会给出提醒（不阻止导出），告诉你去「新建模块」里勾上，或者手动加 `@file:Depends("...")`。
> 「换一张地图」就是这种控件：它会自动加上 `wayzer/maps` 依赖，所以这一条通常不会出现。

### 画布

一张画布 = 一个 `.kts` 文件。画布就是标签页。

| 操作 | 怎么做 |
|---|---|
| 新建画布 | 标签栏最右边的 **+** |
| 切换 | 点标签 |
| 重命名 | 双击标签，或右键菜单「重命名」 |
| 复制一张 | 右键菜单「复制一张」 |
| 关闭 / 删除 | 标签上的 **×**，或右键菜单「删除」 |

**只剩一张画布时不能删。**

新建 / 重命名画布时有两个字段：

- **名字** —— 标签上显示的中文名（比如「进服欢迎」）
- **文件名** —— 生成的 `.kts` 叫什么（比如 `welcome` → `welcome.kts`）。只能用字母、数字、下划线。**留空会自动生成。**

同一个插件组里有多个画布用同一个文件名时会报错（错误，阻止导出）。

## 十六、导出的代码长什么样

一个完整的例子：

```kotlin
@file:Depends("coreMindustry")

package demo

//@14 28 28
listen<EventType.PlayerJoin> {
    val player = it.player
//@2 bo 28 1
    player.sendMessage("[green]欢迎 {player.name} 来到本服务器！".with("player" to player), MsgType.Message, 10f)
//@2 bo 6o 1
    broadcast("[cyan][+] {player.name} 加入了服务器".with("player" to player), MsgType.InfoMessage, 10f)
}
```

**只有 `@file:Depends("coreMindustry")` 一个依赖声明，以及真正需要的 import。** 生成器只在用到时才补 import，所以大多数文件干净得只有依赖 + 包名。

### 那些 `//@` 注释是什么

它们叫**锚点**，是工具为了「从代码还原回画布」留下的记号。就是普通注释，**不影响运行**。

格式是：

```
//@<控件编码> <x> <y> [嵌套层级]
```

- **控件编码** —— 把 `action.broadcast` 这样的名字压成 `2`、`event.PlayerJoin` 压成 `14`。表在 `src/frontend/js/catalog/codes.js`。
  表里没有的控件（比如新加的还没登记）写成 `?完整key`，例如 `//@?action.brandNew 28 28`。这个 `?` 同时也是防误判的标记：短码限定为 1~3 位 base36，就是为了不把你在代码里手写的 `//@TODO fix 42` 错当成锚点。
- **坐标** —— 画布位置，写成 base36（`80` → `28`，`420` → `bo`）。画布坐标恒为整数，所以这样做是无损的。
- **嵌套层级** —— 0 层省略不写。锚点本身顶格，层级靠这个数字记，不靠缩进。

**为什么不写文件头注释，`module.kts` 里一条注释都没有** —— 模块信息那一行 `package demo` 已经写清楚了，没必要再记一遍。

**为什么要把注释抠得这么小** —— 这些注释会跟着代码一起发给使用者，注释越少，用户拿到的插件越干净。改成现在的写法后，**注释占整个文件的体积从约 40% 降到约 10%**：

| | 之前（1.1.0 及更早） | 现在 |
|---|---|---|
| 示例工程 5 个文件合计 | 42.4% | **9.8%** |
| 单文件最差 | 45.9% | 11.3% |

**一个诚实的边界**：只有 **1 个控件**的画布达不到 10% —— 那种文件生成出来的代码本身才 70~230 字节，光一条锚点就有 11~12 字节。实测 52 个能干净生成的单控件画布：平均 **12.0%**，最差的 23.7%，只有 10 个压进 10%。控件越多，注释被摊得越薄。这是已知下限，不打算为它再牺牲可读性。

## 十七、常见问题与排查

### 点了「导出插件」没反应 / 弹了个问题清单

说明还有**错误**没修。清单里的每一条都能点，点了会跳到出问题的那个控件。错误清零后就能导出。

有**提醒**（不是错误）时会问一句要不要继续 —— 提醒不影响导出。

### 「从代码还原」说文件里没有本工具的标记

那个 `.kts` 不是本工具导出的。本工具靠 `//@` 锚点注释还原，手写的代码里没有这些注释。

### 还原出来的控件都是空的

这是**设计如此**，不是 bug。注释里只有「哪个控件、在哪儿、嵌套几层」，**没有表单参数**。参数得重新填。详见[第十一节](#十一从代码导入还原回画布)。

### 还原出来的画布名字不对

同理：为了压注释体积，画布标题没有存进锚点 —— 还原出来的标签固定叫「导入的画布」，只有**文件名**取自你选的那个 `.kts`。双击标签可以重命名。

### 线连不上，提示「已经在……里面了」

连回去会形成死循环，工具挡住了。检查一下是不是把下游的控件连到了自己的上游。

### 一个入口连了两条线，旧的那条没了

这是有意的：**一个入口只能有一条入线**。给已经有入线的入口再连一条，旧的会被替换掉。可以 `Ctrl+Z` 撤销。

### 参数面板里选不到我想要的变量

可选的变量来自**这条链的上游**。如果那个变量是在别的地方声明的（比如另一条分支、或者别的画布），这里就看不到。把声明变量的控件挪到这条链前面，或者调整连线。

### 右边对话框（选目录、保存工程）打不开

那些是 Windows 的系统窗口。如果工具窗口被拖到了另一个显示器、或者最小化了，系统对话框可能出现在别处。把工具窗口切到前台再试。

### 工具窗口关不掉了

关窗提醒弹出时选「取消」会保留窗口。如果**任何反应都没有**（界面完全不响应），说明前端脚本卡住了 —— Rust 侧有个 **2 秒看门狗**：万一前端坏了没人回应，2 秒后会自动放行关闭。所以正常情况下不会出现「关不掉只能强杀」。

如果你真的遇到了关不掉，先试着按 `Esc`（关掉可能开着的弹窗），再点一次 X。

### 关掉窗口会不会丢工作？

**不会。** 本工具每次改动都会自动存进本地存档（默认 400ms 一次），下次打开还能恢复。

关窗时如果提示「有改动还没保存」，那是针对**没存成 `.saproj` 文件**这件事 —— 只有存成文件才能换台电脑用、或者发给别人。弹窗里的三个出口是：**取消 / 不保存 / 保存并继续**。

「未保存」是拿当前内容和上次存盘的**快照对比**算出来的，所以撤销回原样之后它会自动变回「✓ 已保存」，不会一直亮着。

### 导出的代码在游戏里报错

工具**不编译**代码，只做结构校验。可能的排查方向：

1. 依赖勾对了吗？某个控件需要的依赖没勾，校验里会有提醒。
2. 核对一下 [控件参考.md](控件参考.md) 里的说明，看是不是用法不对。
3. 用一个最小的画布（一个事件 + 一个动作）试试，逐步加上去，找到出问题的那一块。
4. 部分下拉项标着「未验证」—— 那些选项的来源不确定，可以换一个再试。
5. 还是不行的话，把日志文件发出来。

### 反馈问题时该给什么

**把日志文件发过来就够了。** 设置在「日志」页有「打开日志文件夹」和「复制全部」。

日志里有：你用的版本、时间、点了什么按钮、报了什么错、当时工程有多大、崩溃前 40 步操作。基本不用再额外描述。
