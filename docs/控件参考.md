# 控件参考

> 怎么用这个工具看[使用手册.md](使用手册.md)；文档总目录见 [README.md](README.md)。

本工具一共提供 **84 个控件**、**10 个分类**，按分类列出。控件库左侧按「入门 / 高级」两档折叠，
同一个分类里入门控件排在前，控件按**两列**排布。

怎么读下面每一节：

- **名字** —— 画布和控件库上显示的中文名，拖进画布看到的就是它。
- **内部标识** —— 控件目录里的 `key`。导出代码的锚点注释里记的就是它（表内控件会压成 1~2 个字符的编码，详见[使用手册](使用手册.md)里的「从代码导入」一节）。
- **级别** —— 入门 / 高级，对应控件库里的分组。
- **代码长什么样** —— 该控件大致会生成哪一行 Kotlin（`codeHint`）。
- **说明** —— 目录里附带的注意事项。

> 这份表是照着 `src/frontend/js/catalog/*.js` 里的控件目录**手工整理**的，不添加目录里没有的信息。
> **控件行为以代码为准** —— 表可能落后于代码，两边不一致时信代码。
> （目录里的 `key`、`label`、`level`、`codeHint` 是权威来源；想核对就用 `tests/coverage.js`，它会遍历全部控件。）

## 事件（当……发生时）

- 代码长什么样：`listen(EventType.Trigger.update)`

## 动作（要做的事）

### 入门（7 个）

#### 发消息

- 内部标识：`action.broadcast`（锚点编码 `2`）
- 代码长什么样：`broadcast("...".with()) / player.sendMessage(...)`
- 要填的参数：发给谁、说什么、显示方式、不在控制台打印

#### 给单位加状态

- 内部标识：`action.applyStatus`（锚点编码 `1`）
- 代码长什么样：`unit.apply(StatusEffects.slow, 5f * 60f)`
- 要填的参数：加什么状态、持续几秒、对哪个单位

#### 生成单位

- 内部标识：`action.spawnUnit`（锚点编码 `k`）
- 代码长什么样：`UnitTypes.dagger.spawn(team, x, y)`
- 产出变量：`newUnit`（单位）
- 要填的参数：生成什么单位、属于哪个队伍、位置、X 坐标、Y 坐标

#### 给物品 / 资源

- 内部标识：`action.giveItem`（锚点编码 `7`）
- 代码长什么样：`team.data().core()?.items?.add(Items.copper, 100)`
- 要填的参数：给什么、给多少、给谁

#### 做一个服务器指令

- 内部标识：`action.registerCommand`（锚点编码 `d`）
- 代码长什么样：`command("名字", "说明") { ... body { ... } }`
- 要填的参数：指令名字、说明、别名（用逗号分隔）、只有玩家能用、需要的权限（留空则人人可用）、冷却（秒，0 = 不限）

> **冷却（秒，0 = 不限）** 默认 `0`，也就是不限制。填了大于 0 的数之后，生成的指令体会先做一次冷却检查：
> 同一个人在这个秒数内重复用会被挡下来，并回一句「冷却中，请稍后再试」。计时按玩家 uuid 分别记，
> 所以冷却不影响别人。这个参数只是给指令体加了一段检查，**指令的出口没有变化**（仍然只有一个出口）。

#### 传送单位到某处

- 内部标识：`action.teleport`（锚点编码 `l`）
- 代码长什么样：`unit.set(x, y); unit.snapInterpolation()`
- 要填的参数：对哪个单位、位置、X 坐标、Y 坐标

#### 消灭单位

- 内部标识：`action.killUnit`（锚点编码 `9`）
- 代码长什么样：`unit.kill()`
- 要填的参数：对哪个单位、消灭范围、哪个队伍

## 条件（如果……就）

### 入门（2 个）

#### 如果……就

- 内部标识：`condition.if`（锚点编码 `n`）
- 代码长什么样：`if (条件) { ... } else { ... }`
- 出口：「就」 / 「否则」
- 要填的参数：条件规则（可加多条，可选「全部满足 / 满足任意一个」）

#### 如果是管理员

- 内部标识：`condition.isAdmin`（锚点编码 `o`）
- 代码长什么样：`if (player.admin) { ... }`
- 出口：「就」 / 「否则」
- 要填的参数：判断谁、玩家名

### 高级（1 个）

#### 不满足就跳过（提前退出）

- 内部标识：`condition.guard`（锚点编码 `m`）
- 代码长什么样：`if (!(...)) return@listen`
- 出口：「满足时继续」 / 「不满足时」
- 要填的参数：多个条件之间（可加多条，全部满足 / 满足任意一个）、不满足时

## 交互

### 入门（3 个）

#### 弹一个菜单

- 内部标识：`interact.openMenu`（锚点编码 `24`）
- 代码长什么样：`Call.menu(player.con, 编号, 标题, 说明, arrayOf(arrayOf(...)))`
- 说明：在玩家屏幕上弹出可点的菜单。要知道他点了哪个，接「玩家选了菜单项」
- 要填的参数：菜单编号、标题、说明文字、选项（一行一个）、跟随式（一直占着屏幕）

> 「选项（一行一个）」是模板框：**每一行非空的文字会变成菜单里的一项**，
> **默认竖排展示**（一行一个按钮，`arrayOf(arrayOf("A"), arrayOf("B"))`）——不会横排挤在一起。
> 「跟随式」勾上时生成 `Call.followUpMenu(...)`，不勾就是 `Call.menu(...)`。
> 这个控件需要一个上游的**玩家**变量 —— 挂到「玩家进服」「玩家发言」这类事件下面。

#### 玩家选了菜单项

- 内部标识：`interact.onMenuChoose`（锚点编码 `25`）
- 代码长什么样：`listen<EventType.MenuOptionChooseEvent>`
- 说明：玩家点了菜单里某一项时触发。选项编号「第几项」从 0 开始数
- 可以作为画布的起点单独放。
- 要填的参数：菜单编号
- 这个事件给你的变量：`player`（玩家）、`option`（数字）

> 菜单编号要和「弹一个菜单」里填的**一样**，编号对不上就直接跳过。
> 这样同一张画布能放好几套菜单，各自只听自己的号；`option` 是玩家点的是第几项（从 0 数）。

#### 让玩家打开一个网址

- 内部标识：`interact.openURI`（锚点编码 `27`）
- 代码长什么样：`Call.openURI(player.con, "https://...")`
- 说明：用游戏内的确认框问玩家要不要打开这个网址
- 要填的参数：网址

> 这个控件也需要一个上游的**玩家**变量。

### 高级（1 个）

#### 关掉菜单

- 内部标识：`interact.closeMenu`（锚点编码 `26`）
- 代码长什么样：`Call.hideFollowUpMenu(player.con, 编号)`
- 说明：主动收起一个跟随式菜单；普通弹出式菜单会自己消失，不用管
- 要填的参数：菜单编号

> 只有「跟随式（一直占着屏幕）」的菜单才需要主动收；编号要和「弹一个菜单」里填的一样。

## 服务器

### 高级（4 个）

> 这一整类都在控件库的「高级」档里。

#### 停用这个插件自己

- 内部标识：`server.disableSelf`（锚点编码 `28`）
- 代码长什么样：`thisContextScript().let { s -> launch(Dispatchers.game) { ScriptManager.disableScript(s, "原因") } }`
- 说明：让这个插件把自己关掉，并往日志里写一句原因。适合「配置不对就别跑」这种情况
- 要填的参数：原因（会写进日志）

#### 换一张地图

- 内部标识：`server.loadMap`（锚点编码 `29`）
- 代码长什么样：`MapManager.loadMap()` / `launch(Dispatchers.game) { MapRegistry.findById(编号)?.let { MapManager.loadMap(it) } }`
- 说明：换下一张地图，或换到指定编号的地图。需要 maps 模块
- 要填的参数：换成哪张（下一张（轮换） / 指定编号）、地图编号

> 选了「指定编号」才会出现「地图编号」那一栏；编号错了会静默不换。
> 这个控件会自动加上对 `wayzer/maps` 的依赖。

#### 设置某个队伍的属性

- 内部标识：`server.teamRule`（锚点编码 `2a`）
- 代码长什么样：`state.rules.teams.get(Team.get(1)).cheat = true`
- 说明：改一个队伍的整体属性：作弊模式、无限资源、各种倍率
- 要填的参数：队伍编号、改哪一项、设成什么

**「改哪一项」的 24 个选项：**

| 类型 | 字段 |
|---|---|
| 开关（9 个） | `cheat` 作弊模式（无限资源、秒建）、`infiniteResources` 无限资源、`fillItems` 核心自动补满物品、`aiCoreSpawn` AI 自动造核心、`protectCores` 保护核心、`checkPlacement` 检查建筑放置位置、`prebuildAi` AI 预先建造、`buildAi` AI 自动建造、`rtsAi` RTS 模式 AI |
| 整数（2 个） | `rtsMinSquad` RTS 最小队伍规模、`rtsMaxSquad` RTS 最大队伍规模 |
| 小数（13 个） | `buildAiTier` AI 建造等级、`rtsMinWeight` RTS 最小权重、`unitFactoryActivationDelay` 工厂激活延迟、`unitBuildSpeedMultiplier` 单位建造速度倍率、`unitDamageMultiplier` 单位伤害倍率、`unitCrashDamageMultiplier` 单位坠落伤害倍率、`unitMineSpeedMultiplier` 单位采矿速度倍率、`unitCostMultiplier` 单位造价倍率、`unitHealthMultiplier` 单位生命倍率、`blockHealthMultiplier` 建筑生命倍率、`blockDamageMultiplier` 建筑伤害倍率、`buildSpeedMultiplier` 建造速度倍率、`extraCoreBuildRadius` 核心额外建造范围 |

> **「设成什么」怎么填**：开关类接受 `true` / `1` / `是` / `开` / `on`（不区分大小写）表示「开」，
> 其它一律当「关」。数字类直接填数字；小数类生成的代码会**自动带上 `f` 后缀**
> （Kotlin 的要求，不带编译不过），这一点不用你操心。

#### 注册一个显示变量

- 内部标识：`server.registerVar`（锚点编码 `2b`）
- 代码长什么样：`registerVar("名字", "说明", DynamicVar { 值 })`
- 说明：注册一个 `{名字}` 占位符，之后在任何消息里都能用。计分板和广播都认它
- 可以作为画布的起点单独放。
- 要填的参数：变量名字、说明、显示什么、表达式（仅在「自己写表达式」时填）

**「显示什么」的 7 个选项：**

| 选项 | 值 |
|---|---|
| 当前玩家数量 | `players` |
| 当前波数 | `wave` |
| 当前剩余敌人数 | `enemies` |
| 当前地图名 | `mapName` |
| 服务器 TPS | `tps` |
| 内存占用(MB) | `heap` |
| 自己写表达式 | `custom`（选了它才会出现「表达式」那一栏） |

> 注册出来的变量可以从别的插件 / 占位符里引用。
